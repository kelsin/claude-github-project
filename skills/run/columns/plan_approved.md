# Column: Plan Approved

1. If `split.approved` from `prepare` lists sub-stories, the plan was split and the parent is never implemented: when `split.created` is empty or shorter than `split.approved` run `CGP split <item>` (it is safe to rerun: it creates only what is missing) (it creates exactly the approved sub-stories in Todo, each with its plan skipped), post a status comment listing them, and stop WITHOUT moving. The parent is not implemented: the loop leaves it waiting and closes it when every sub-story is Done by a merged PR. Either way stop after this step. A refusal (for example the plan was approved by the policy, not a person) goes to the user with `CGP ask`. Otherwise (no split) continue.
2. Rule 1. Run `CGP overlap <item>` (refresh `CGP touches` from the approved plan first if it is missing). If `suggest.action` is `declare`, run `CGP touches` from the plan and repeat. If it is `block`: `CGP block <item> <other>` for each story in `on` (if `block` refuses because of a cycle, the other story now ranks behind you: `CGP block <item> --unblock` and continue), post a status comment saying which stories you wait on and which files overlap, and stop WITHOUT moving (the loop skips blocked stories and releases this one when they are Done). Otherwise (`proceed`) run `CGP block <item> --unblock` in case an old block is left, and continue. If the story is held by a GitHub dependency ("blocked by" on GitHub, shown under `blocked` in `CGP list --brief`), `--unblock` does not clear it and neither may you: stop WITHOUT moving and reply `waiting:`.
3. `CGP move <item> implement` (the story is in Plan Approved, which only the user sets, so this move is allowed from it). Read the approved plan artifact and any human comments on it.
4. Continue with `implement.md` (the same folder), the no-`pr` path, from step 2: rule 1 is already done and `prepare` was run, so skip it, but run `CGP sync <item>` once more before writing code (rule 7).
